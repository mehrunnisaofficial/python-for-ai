# 🧠 The "20-minute stuck rule"

This one is important.

Suppose you're building your own project and think:

> "How do I make Python do X?"

Don't immediately ask me.

Try this:

### 1. Think

"What do I already know that could help?"

### 2. Search the documentation

Google something specific.

Bad:

> `python project help`

Good:

> `Python pathlib rename file`

### 3. Search examples

Look at **how other people use the feature**, but don't copy the entire project.

### 4. Try something stupid

Seriously.

Write the ugly version.

```python
# I have no idea if this works
```

Try it.

It fails.

Good.

Now you have a **specific problem**.

### 5. Then ask me

Instead of:

> "Make this project for me."

you can ask:

> "I'm trying to move `.pdf` files into a folder. I wrote this, but it's giving me X error. Explain what's wrong without writing the solution."

THAT kind of question will make you improve ridiculously faster.

# 4. Recommendation Roulette

### Original Idea

I want to build a personal recommendation system that helps me decide what to read or watch when I don't know what to choose.

Instead of showing me a huge list of recommendations, the system should ultimately give me **only one recommendation**.

I should be able to tell the program what kind of experience I want, such as:

* Genre.
* Mood.
* Type of story.
* Length.
* Language.
* Era.
* Fiction or non-fiction.
* Book, novel, movie, or series.
* Other preferences that I gradually add to the system.

The system should then use these preferences to create a pool of possible choices and use a random selection mechanism to choose one final recommendation.

### Core Idea

The goal is not to build another search engine that gives me hundreds of results.

The goal is:

**Tell the system what I want → let the system make the decision → get ONE thing to read or watch.**

For example:

Input:

Genre: Mystery
Mood: Dark
Format: Novel

Output:

🎲 **One randomly selected recommendation**

The recommendation should come with enough information for me to decide whether I want to accept the challenge.

### Important Rule

Once the system gives me a recommendation, I should actually experience it rather than immediately asking for another recommendation.

For example:

**Recommendation → Read/Watch → Finish → Record experience → Return to the system**

This could eventually become part of a personal reading and watching tracker.

### Initial Version

Start with a small manually created collection of books, novels, movies, and series.

Each item can contain information such as:

* Title.
* Type.
* Genre.
* Mood.
* Language.
* Year.
* Length.
* Rating or personal score.
* Tags.

The program should:

1. Ask what type of thing I want.
2. Ask for some preferences.
3. Filter the collection.
4. Randomly select one suitable item.
5. Display only that recommendation.

### Future Recommendation System

As the project develops, the random selection should become more intelligent.

Instead of every matching item having exactly the same chance, different preferences could affect the probability of selection.

For example:

A recommendation could receive points based on how closely it matches my preferences.

Then randomness could be applied among the items with suitable scores.

This creates a balance between:

**Personalization + Randomness**

The system should still surprise me instead of always giving me the most obvious choice.

### Reading / Watching History

Eventually, the system could remember:

* What I was recommended.
* Whether I accepted it.
* Whether I finished it.
* When I finished it.
* My personal rating.
* What I liked about it.
* What I disliked.
* Whether I would recommend it to someone else.

This history could then influence future recommendations.

### Long-Term Possibilities

The project may eventually include:

* Larger databases of books and movies.
* APIs for retrieving information.
* Personal preference profiles.
* Recommendation scoring.
* Weighted randomness.
* Reading history.
* Watch history.
* Reviews and ratings.
* Genre and mood analysis.
* Similar-item recommendations.
* Recommendation explanations.
* SQLite/database storage.
* GUI or web interface.
* Eventually machine-learning-based recommendations.

### Possible Expansion

The project could eventually become a broader personal discovery system rather than only a book recommender.

It could recommend:

📚 Books
📖 Novels
🎬 Movies
📺 Series
🎧 Music
📰 Articles
🧠 Research topics

The central concept remains the same:

**Give me one interesting thing I probably would not have chosen myself.**

### Development Philosophy

Do not begin by trying to build an advanced recommendation algorithm.

Start with:

**Collection → Filters → Random choice**

Then gradually introduce:

**Scoring → Weighted randomness → Personal history → Personalization → Intelligent recommendations**

The system should become more sophisticated only when I understand the technology required to build each stage.
